# Phone-first OCR and CPU model evaluation — 9 September 2026

## Implemented split

| Device/browser | Pokget server |
|---|---|
| Camera/file orientation, guide crop and bounded JPEG preparation | Authenticated, CSRF-protected, rate-limited `/api/scan` |
| Tesseract 7 WASM in workers; enlarged top/bottom OCR regions | Active catalog filtering by selected TCG/language |
| One selected language; cached language data; reusable OCR session | Deterministic name/collector evidence and review candidates |
| Text-only JSON submission when local OCR succeeds | Optional local Ollama selector for different-card ambiguity |
| Abort/20-second local timeout; release workers when idle or hidden | Five-second model budget; canonical ID validation; mandatory review |

Auto language detection, unsupported devices, unreadable local OCR, and no catalog
candidate fall back to the existing image-upload pipeline. Ambiguous matches do
not automatically upload images: the user can request **Use server image scan**.
All OCR code and language files are self-hosted. There is no phone-side LLM,
catalog download, provider credential, native NPU, or native ML Kit integration.

## CPU model selection

Selected [`qwen2.5:1.5b`](https://ollama.com/library/qwen2.5:1.5b) (Q4_K_M), four threads, temperature 0, seed 42, 2,048-token
context, 128 output-token limit, CPU only. Ollama 0.32.3 ran in a separate
four-CPU/9-GiB container on a Xeon Gold 6126 host. `/api/ps` recorded
`size_vram: 0` and about 1.11 GB loaded size. The host was shared with development
and browser testing; timings are exploratory, not dedicated-hardware guarantees.

Each model received ten identical cases with shuffled candidate positions:
three saved real-card Tesseract outputs, four synthetic language outputs, one
synthetic OCR error, and two abstention cases. Five candidates were supplied;
expected answers and evidence scores were not sent to the model. Short request-local
IDs were constrained by a JSON schema. Correct means the exact expected selection
or abstention, with a complete, valid response.
Request options and timing fields follow the [Ollama generate API](https://docs.ollama.com/api/generate)
and [structured-output contract](https://docs.ollama.com/capabilities/structured-outputs).

| Model | Correct / 10 | Median request time |
|---|---:|---:|
| gemma3:270m | 2 | 4.72 s |
| qwen2.5:0.5b | 1 | 3.37 s |
| **qwen2.5:1.5b** | **7** | **5.49 s** |
| gemma3:1b | 6 | 7.43 s |
| llama3.2:1b | 5 | 4.26 s |
| qwen3.5:0.8b, thinking disabled | 3 | 5.07 s |
| qwen3.5:2b, thinking disabled | 6 | 11.03 s |

Earlier runs accidentally left the expected answer first because PowerShell
`Sort-Object card_id` did not sort ordered dictionaries as intended. Those runs
are **invalid for accuracy comparisons and excluded here**. Explicit dictionary
key sorting corrected this; the repeatable corpus has counterbalanced positions.

### Final model-only test using actual browser OCR

The selected model was tested twice on 31 unique inputs: six real-card scans
(five distinct English cards plus a Furret JPEG variant), seven synthetic language
fixtures, thirteen synthetic noise/disambiguation cases, and five abstentions.
The first thirteen inputs use captured browser OCR including enlarged edge passes.

| Measure | First pass | Warm repeat pass |
|---|---:|---:|
| Correct across all 31 cases | 23/31 | 22/31 |
| Correct real-card candidate selections | 6/6 | 6/6 |
| Correct synthetic-language selections | 6/7 | 6/7 |
| Correct abstentions | **0/5** | **0/5** |
| Median elapsed request time | 4.705 s | 1.564 s |
| p95 elapsed request time, nearest rank | 11.871 s | 2.094 s |

The first model request took 14.782 seconds. Warm repeat timings can benefit from
caching and must not be presented as cold latency. Combined correctness was
45/62; repeats do not create 62 independent test cases. Japanese and some noisy
Lorcana inputs remained weak. One synthetic Yu-Gi-Oh selection differed between
passes despite deterministic sampling settings.

**This is not end-to-end detection accuracy.** The isolated test deliberately
supplies irrelevant candidates for abstention probes. Production first requires
catalog evidence, skips empty/unique/same-name-only choices and clear printed
identities, validates returned IDs, and always requires device-text confirmation.
The model alone is not safe as an abstention or confidence estimator. A cold or
slow model cannot exceed the five-second optional selection budget; local review
candidates remain available when it times out.

## Browser and pipeline verification

Chrome 152, 390×844 mobile viewport, on the desktop host—not a physical phone:

- Full-card plus enlarged-edge OCR: **1.23–2.72 seconds** for the six English scans.
- Enlarged regions recovered Furret's `136/189` and the complete `Aggron ex` name.
- All seven language packs loaded successfully: English, German, French, Japanese,
  Simplified Chinese, Traditional Chinese, Korean. Synthetic typography took
  0.22–0.97 seconds; Korean still read the `ex` suffix imperfectly.
- The deterministic matcher retained the expected card in review candidates for
  all 13 browser fixtures; it ranked the expected card first in **12/13**.
  Plain Aggron ranked ahead of Aggron ex on a stray rules-text number without
  model help. An integration test verifies the optional local selector can reorder
  that ambiguity without contacting the primary provider or removing review.
- The real scanner UI and Go handler matched the Furret 136 fixture end to end.
  Network inspection showed **one 825-byte JSON POST**, no image upload, and
  `processing: "device_ocr"`, `requires_image: false`, `needs_review: true`.
- All OCR assets came from the same local origin. Native Tesseract emitted one
  diacritics diagnostic during a noisy image read; no application exception or
  failed OCR asset request occurred. The test host has no camera.

There are **not five real cards per language** in this corpus. Glare, handheld
capture, low-memory phones, Safari/iOS, mobile radio downloads, and NPU performance
remain unmeasured. The fallback and explicit review are intentional safeguards.

## Reproduce

The captured, shuffled selector corpus is committed at
[`testdata/ocr/device-selection.json`](../testdata/ocr/device-selection.json).
Use an isolated Ollama instance with the selected model already pulled; the
benchmark deliberately unloads models before and after testing:

```powershell
pwsh -File scripts/benchmark-ollama-text.ps1 -BaseUrl http://127.0.0.1:11436 -Models qwen2.5:1.5b -Repeats 2
```

This script uses no API keys and writes incremental results under `artifacts/benchmarks/`.
The recorded final run is `artifacts/benchmarks/ollama-text-device-final-20260909/`;
browser transcriptions are `artifacts/benchmarks/device-ocr-browser-20260909.json`.
Those generated artifacts are local and ignored by Git.

```bash
npm ci --ignore-scripts
npm run build:static
npm run check:static
npm run test:static
go test ./internal/service ./internal/handlers ./internal/middleware ./cmd/pokget
```

Windows backend checks used `CGO_ENABLED=0`; real Tesseract execution was verified
in the browser. Native server-image OCR should also run through the existing Linux
CGO integration gates before deployment. Dependency audit found zero known
vulnerabilities; 65 registry signatures and 11 attestations verified.
